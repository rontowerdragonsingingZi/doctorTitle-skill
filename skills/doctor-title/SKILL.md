# 医疗标题与三件套协调器

## 必须加载

1. 先阅读 [工作流与命令](references/workflow.md)、[合规规则](references/compliance.md) 和 [标题方法](references/title-guide.md)。
2. 用宿主的 Skill 加载工具加载 `doctor-title`、`doctor-article`、`doctor-img`。工具未发现时执行 `scripts/workflow.py preflight`，读取返回的三个 `SKILL.md` 及其必要引用。搜索已安装目录、兄弟仓库和 `C:\demo`；不能把“找到文件”说成“已读取”。
3. 不同安装路径可用 `--skills-root` 或 `DOCTOR_SKILLS_ROOT` 明确指定共同父目录。缺少任何一个 Skill 就暂停，报告缺失名称和已检查路径，提示安装或加载。不得自行忽略依赖，也不得擅自下载、安装或改宿主配置。
4. 三件套齐全不代表有生图工具；无生图工具仅可跳过图像生成，不可跳过 `doctor-img` 的提示词与视觉规范步骤。

## 按序执行

1. 运行 `context`，读取全部压缩记忆和当日阈值。不得先写完选题再补看历史。首次运行建立本地日期基线，后续不重置。
2. 从五类范围中的具体症状、生活场景、认知误区或就医判断切入。不局限于疾病大类，但必须有清晰医学关联。不索取可识别患者信息。
3. 内部生成多个差异化候选，以问句、误区纠正、场景冲突、行动边界形成吸引力。不得用诊断暗示、性羞辱、恐吓、医生背书或疗效保证换取点击。
4. 按 [输入模板](assets/draft.example.json) 写 UTF-8 JSON 草稿。`check --draft <路径>` 可先检查仅含标题与特征的草稿。必须同时做语义复核，不能用换标点、换同义词绕过去重。
5. 锁定一个合规且相似度通过的标题，交给 `doctor-article` 生成正文及特征摘要。再由 `doctor-img` 使用同一标题及正文含义生成 Banner 或完整提示词。任何标题变更都回到本步骤前重新检查，并同步两个下游。
6. 正文完成后再次 `check`，对照接近的历史记录做语义审查。若正文、摘要或标题超阈值，重选角度并重写，不能只替换摘要、删除记录或提前放宽阈值。
7. 完成医学、合规、原创与语义人工/Agent 审核；有图还需视觉审核。填写完整产物 JSON，执行 `archive --draft <路径>`。脚本再次校验依赖、阈值、审核项、图像尺寸及文件名并落盘。
8. 向用户返回原始标题、正文路径、图片路径或跳过原因及提示词所在路径、相似度/阈值。阈值到 40% 必须明确提醒已达到上限，不自动继续提高。候选耗尽则停止该次产出并说明原因。

## 禁止误报

- “爆款”是文风目标，不保证阅读量或转化。
- 程序分数是可复算的文本特征重合度，不是医学事实审查或语义模型保证。
- `review` 与 `loaded_skills` 是执行者的审核声明，不可未检查就全填 `true`。
- 只在完整归档成功后报告完成；失败、仅候选和未采用文章不写入正式历史。
- 脚本不会调用大模型、自动发公众号、自动上传素材或联网诊断。
